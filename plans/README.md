# Animation improvement plans

Generated by `/improve-animations` (standard effort, full interactive-UI audit) at commit `5e82fe8`. Marketing (`components/marketing/`) was audited and fixed separately in an earlier pass this session — these 14 plans cover the CRM application UI only (core chrome, section dialogs/forms, dashboard/analytics data-viz).

Every plan is self-contained and stamped against commit `5e82fe8`. If you run `execute <plan>` in an isolated worktree per plan, there is no ordering dependency between them — each is independently correct against that commit. If you instead apply them sequentially in one working tree, follow the order below, since several plans touch the same file (`tailwind.config.ts`, `app/globals.css`) and each plan's "current code" snippet already accounts for what an earlier plan in this order would have added.

## Recommended execution order

1. **001, 002, 003, 004, 005** — all HIGH severity, all trivial/isolated (1-3 line changes, no shared files with each other). Do these first, any order among themselves.
2. **006** — touches `tailwind.config.ts` and `app/globals.css`; do before 007/013 since it introduces the reduced-motion `@media` block those two plans extend.
3. **007** — extends the reduced-motion block from 006; also the source of the `menu-in` token that 013 reuses.
4. **013** — reuses `menu-in` from 007 (self-contained fallback included if 007 hasn't run).
5. **008** — independent, but logically pairs with 004 (both fix the same file's animation approach — 004 fixes easing only, 008 replaces the mechanism entirely). Apply 004 first if doing both, so 008's "current code" match includes 004's easing-only diff... actually 008 fully replaces the file, so either order works; 004 becomes moot once 008 runs since 008 stops using `animate-toast-in`/`animate-toast-out` classes entirely. **If applying both, apply 008 last** — it supersedes 004's fix for `toaster.tsx` (004's `tailwind.config.ts` change is harmless to leave in place either way, just unused after 008).
6. **009** — independent.
7. **010** — independent, but reads `button.tsx` to check whether 003 already ran (handles either order explicitly).
8. **011, 012, 014** — independent of everything else and each other; do these last as they're the lowest-priority "missed opportunity" polish.

## Dependencies

- **013 depends on 007** for the `menu-in` token (013's plan text includes a self-contained fallback definition if 007 hasn't run — no hard blocker, just apply 007 first to avoid defining `menu-in` twice).
- **010 depends on knowing whether 003 has run** (handled explicitly inside plan 010's steps).
- **008 supersedes 004** for `components/notifications/toaster.tsx` specifically (004 only fixes `toast-out`'s easing; 008 replaces the whole entrance/exit mechanism and stops using that keyframe animation entirely). No conflict if both are applied — 008 simply makes 004's toaster-visible effect moot while 004's `tailwind.config.ts` edit remains harmless.
- **006 and 007 both touch `app/globals.css`'s reduced-motion block** — apply 006 first so 007 can extend the existing block instead of creating a duplicate `@media` rule (both plans' text handles either order explicitly).
